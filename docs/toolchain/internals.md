# mincc の内部設計

コンパイラを改造する人向けです。言語仕様側は [mincc.md](mincc.md)。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `mincc/main.c` | 標準入力の読み込み、crt0 と割り込みベクタの出力、全体の駆動 |
| `mincc/parse.c` | トークナイザ（`tokenize`）とトークン消費ヘルパ（`consume` / `expect` / `check_type`） |
| `mincc/ast.c` | 再帰下降パーサ。文法は `ast.h` 冒頭のコメントが一次資料 |
| `mincc/nodes.c` | AST ノード生成、シンボルテーブル（`Vars_List` / `Ident_Name`）、スコープ |
| `mincc/codegen.c` | コード生成 |
| `mincc/errorhandle.c` | 位置つきエラー・警告 |

パースとコード生成は完全に分離されています。`main()` は
`program()` で AST を全部作ってから、ベクタテーブル → crt0 →
`generate_top()` の順に出力します（`[[isr=N]]` の有無を知るために
パースを先に終える必要があるため）。

## 呼び出し規約

```
・引数は左から順に r2, r3, ... に入れる（1バイト型は1本、2バイト型は2本）
・r0-r5 は caller-saved（呼び出す側が退避）
・r6 以降は callee-saved（呼ばれた側が使う分だけ退避）
・戻り値は r0（1バイト）または r0:r1（2バイト、r0 が下位）
・Y (r14:r15) がフレームポインタ
・式の評価は r2 から上を「レジスタスタック」として使う
```

| レジスタ | 用途 |
| --- | --- |
| `r0`, `r1` | 戻り値。またどの文の境界でも死んでいるスクラッチ |
| `r2`–`r5` | 引数 / 式評価用（caller-saved） |
| `r6`–`r11` | 式評価用（callee-saved） |
| `r12:r13` (X) | グローバル変数・デリファレンスのアドレス保持。毎回作り直すので保存されない |
| `r14:r15` (Y) | フレームポインタ |

## レジスタスタック（regstack）

式の評価は**レジスタをスタックとして使うスタックマシン**です。
`r2` を底として、部分式の値を上へ積んでいきます。

```c
int push_regstack(int size);  // size バイト積む。積んだ先頭のレジスタ番号を返す
int pop_regstack(int size);   // size バイト降ろす
int chg_regstack(int size);   // 積みも降ろしもせず、上から size バイト目を見る
int set_regstack(int value);  // スタックトップを強制設定（関数境界で使う）
```

たとえば `a + b * c` は

```
r2 <- a
  r3 <- b
    r4 <- c
  r3 <- r3 * r4     (pop して r3 に結果)
r2 <- r2 + r3
```

のように評価されます。

**`push_regstack` は命令を1つも出しません。** 「その関数が最大どこまで
レジスタを使ったか」（`cur_regstack_max`、高水位）を記録するだけです。
実際の `push`/`pop` はプロローグ・エピローグが1箇所でまとめて出します。

### なぜ高水位方式なのか

以前は「そのレジスタを初めて使う場所で `push` を出す」実装でした。これは
2通りに壊れます。

- **ループの中で初めて使った場合**: `push` が反復ごとに実行されるのに
  `pop` は1回しかない。1反復ごとにスタックが1バイト漏れ、`blink.c` のような
  無限ループではグローバル変数領域まで食い潰す。
- **通らなかった分岐の中で初めて使った場合**: `push` が実行されないのに
  エピローグは `pop` する。

そこで、**関数本体を2回生成する**方式になりました。

## 関数本体の2パス生成

`ND_FUNC_DEF` は本体を2回生成します（`codegen.c`）。

```
1回目: g_mute++ して出力を捨てる。cur_regstack_max（高水位）を測るためだけ
       ラベルカウンタは label_mark() / label_rewind() で巻き戻す
2回目: 測った高水位を持ってプロローグを出し、本体を本当に出力する
```

すべての出力は `emit()` を通り、`g_mute` が立っている間は捨てられます。

2回目の前に `cur_regstack_max` を高水位で**シードし直す**のが重要です。
`ND_RETURN` は自前でエピローグを出すので、関数中のすべての `return` が
プロローグと同じレジスタ範囲を pop する必要があるためです。

## プロローグとエピローグ

```asm
func:
        push r15              ; 呼び出し元の Y を退避
        push r14
        push r6               ; callee-saved レジスタ（高水位まで）
        push r7
        ldm  r14,0            ; Y = SP  （フレームポインタ確立）
        ldm  r15,1
        stm  Y-1,r2           ; 引数をフレームへ書き出す
        stm  Y-2,r3
        decs 2                ; ローカル変数分 SP を下げる
        ...本体...
        mov  r0,r2            ; 戻り値を r0(:r1) へ
        mvi  r1,0
        stm  0,r14            ; SP = Y  （フレームを巻き戻す）
        stm  1,r15
        pop  r7               ; callee-saved を復元
        pop  r6
        pop  r14
        pop  r15
        ret
```

要点:

- **callee-saved の push はフレームポインタのロードより上**にあります。
  したがって `Y` は退避したレジスタの**すぐ下**を指します。
  エピローグが `pop` の前に `SP = Y` を実行するのはこのためで、
  結果として**本体は SP をどこに残しても構いません**。
- 逆に言うと、**関数内のスタック不均衡は return 時に見えません**
  （`SP` が `Y` から再ロードされるため）。バグは「戻らない関数」で初めて表面化します。
- 戻り値を先に `r0`/`r1` へ移してから復元します。復元は callee-saved を
  上書きするので、戻り値がそこに乗っていると壊れるためです。
- フレーム確保は `decs n` 1命令です（以前は `mvi`×2 + `add` + `adc` + `stm`×2 の
  6命令で、`r0`/`r1` を潰していました）。256 バイト以上のフレームでは
  旧来の6命令にフォールバックしますが、その前に `check_rp_ofs()` が
  「変位が6bitに入らない」として弾きます。

### ローカル変数のアドレッシング

ローカル変数は `Y` からの負のオフセットでアクセスします。

```asm
ldm r2,Y-1        ; 1バイト変数
ldm r2,Y-2        ; 2バイト変数の下位
ldm r3,Y-1        ; 　　　　　　　上位（リトルエンディアン）
```

変位は**符号付き6bit**（`-32`〜`31`）しかないので、
`check_rp_ofs()` が全アクセス地点で範囲を検査し、超えたら
コンパイルエラーにします。`mincasm` で黙って切り詰められるのを防ぐためです。

### グローバル変数のアドレッシング

グローバルは絶対アドレスですが、コード生成は X ポインタ経由です。

```asm
mvi r13,1         ; アドレス上位
mvi r12,0         ; アドレス下位
ldm r2,X+0
```

（絶対アドレッシング `ldm r2,0x100` を使えば1命令で済むはずですが、
現状は X 経由のままです。）

## ISR のプロローグ・エピローグ

`[[isr]]` の関数は通常と別の入口・出口を使います
（`generate_isr_prologue` / `generate_isr_epilogue`）。

```asm
isr:
        push r1            ; r0/r1 を無条件退避
        push r0
        push r15           ; Y
        push r14
        push r13           ; X（isr_x_save）
        push r12
        push r2            ; 本体が触った分すべて（callee_save_lo() が r2 を返す）
        ...
        ldm  r14,0
        ldm  r15,1
        decs n
        ...本体...
        stm  0,r14
        stm  1,r15
        pop  ...
        pop  r12           ; X（isr_x_restore）
        pop  r13
        pop  r14
        pop  r15
        pop  r0
        pop  r1
        reti
```

通常の関数との違い:

| 項目 | 通常 | ISR |
| --- | --- | --- |
| 退避の下限 `callee_save_lo()` | `r6` | **`r2`** |
| `r0`/`r1` | 退避しない（caller-saved） | 無条件に退避 |
| X (`r12:r13`) | 退避しない | 本体全体を囲んで退避 |
| 終端命令 | `ret` | `reti` |

ハードウェアは汎用レジスタを一切自動退避しないので、
**割り込みには「事前に退避しておいた呼び出し元」が存在しません**。
そのため ISR は自分が触るものすべてを自分で守ります。

`r0`/`r1` の無条件退避は、もともとフレームサイズ計算が `r0`/`r1` を
潰していたための措置でした。`decs` 化でそれは無くなりましたが、
`sei()`/`cli()` とグローバル変数・デリファレンスのアドレスロードが
今も `r0`/`r1` を使うため、退避は残しています。

### X 退避のネスト

`ND_GLOBAL_VAR` の ISR 側の分岐では、**先に `push_regstack()` で
書き込み先レジスタを確保してから** `r12:r13` を触ります。
`push_regstack` が引き起こす退避 push は関数エピローグまで生存するので、
`push r13`/`push r12` とそれに対応する `pop` の**間に入り込ませない**
ためです。

## 生成される命令列のパターン

| C の構文 | 生成される形 |
| --- | --- |
| `if (c) S` | 条件を評価 → `or` で 2バイトを畳む → `jz 終端,rN` → S |
| `if (c) S else T` | 上に加えて S の末尾に `jr 終端` |
| `while (c) S` | `開始:` 条件 → `jz 終端` → S → `jr 開始` |
| `for (i;c;u) S` | `i` → `開始:` `c` → `jz 終端` → S → `u` → `jr 開始` |
| `break` | `jr` で現在のループ終端ラベルへ |
| `a == b` (8bit) | `sub` → `chz` |
| `a != b` (8bit) | `sub` → `chz` → `chz` |
| `a < b` (8bit) | `lt` |
| `a >= b` (8bit) | `lt` → `chz` |
| `a < b` (16bit) | `sub`(下位) → `ltc`(上位) → 結果を下位へ → 上位を0に |
| `!a` (8bit) | `chz` |
| `a && b` | `chz`×2 → `or` → `chz`（短絡なし） |
| `char` → `int` | `mvi rN,0`（上位バイトに0を積む） |
| `int` → `char` | `pop_regstack(1)`（上位バイトを捨てるだけ。命令は出ない） |

ループ終端ラベルは `current_end` というグローバルで管理されています
（`get_unique_label(true)` が更新、`get_break_label()` が読む）。
ネストしたループの `break` は最も内側を抜けます。

## 関数呼び出しの展開

```asm
push r1            ; r0/r1 を退避
push r0
push r2            ; 引数を置くレジスタを退避してから
mvi  r2,2          ; 引数を評価
push r3
mvi  r3,3
push r4            ; 引数に使わなかった caller-saved も退避
push r5
calr add
pop  r5            ; 全部戻す
pop  r4
pop  r3
pop  r2
mov  r2,r0         ; 戻り値を regstack へ
pop  r0
pop  r1
```

`set_regstack(ast_min)` で引数評価用にスタックを一旦 `r2` へ戻し、
呼び出し後に `set_regstack(before)` で元に戻します。

## エラーハンドリング

`errorhandle.c` の `error_at(loc, fmt, ...)` / `warn_at` がソース位置つきの
診断を出します。`loc` はトークンの元ソース内ポインタです。
パーサは各関数に `char *l` を回して現在位置を持ち歩いています。

## デバッグ出力

`mincc` は標準エラーへ大量のログを出します（入力ソース全文、
変数の追加とアドレス、識別子の解決、AST のダンプ）。
`2>/dev/null` で捨てるか、パイプで受けて読んでください。

## 改造するときの注意

- **ISA を変えるなら3箇所同時**（[docs/README.md](../README.md) 参照）。
- コード生成を変えたら `make test` で全ケースを通してください。
  エンドツーエンドのテストしかないので、壊れるとシミュレーション結果が
  変わって落ちます。
- 出力バイト列が変わると `example/*.hex` と食い違います。必要なら再生成してください。
- 既知の不具合は [known-issues.md](../known-issues.md) にまとめてあります。
  改造前に一読を推奨します。
