# minc CPU 概要

`verilog/minc_h.sv` が **リファレンス実装** です。以下の説明は特に断りがない限り
`minc_h.sv` のものです（他の実装との差は [cores.md](cores.md)）。

## 設計方針

目標は「**C言語が動く最小のCPU**」であり、そのために次を捨て、次を残しています。

**捨てたもの**

- 16/32ビットのデータパス（8ビット固定）
- 複雑なアドレッシングモード
- 汎用の即値ALU命令（`adi` 等は削除済み。即値は `mvi` でレジスタに置く）
- フラグレジスタの豊富さ（キャリー1本だけ。ゼロ判定は `chz` 命令で値として作る）
- 分岐条件の種類（条件分岐は「レジスタが0なら飛ぶ」`jz` 1つだけ）
- 割り込み時の汎用レジスタ自動退避（コンパイラ側で解決）

**残したもの（Cを効率よく動かすために必須と判断したもの）**

- ハードウェアスタックポインタと `push`/`pop`/`calr`/`ret`
- レジスタペア + 符号付き変位のアドレッシング `ldm/stm rp+n`
  （ローカル変数のフレームポインタ相対アクセスがこれ1命令で済む）
- 絶対アドレッシング `ldm/stm n`（グローバル変数とMMIO用）
- `mul`/`mulh`（8×8→16 の乗算）
- スタックポインタを一括で下げる `decs`（スタックフレーム確保用）

結果として **約371 LUT / 77 FF** に収まっています
（[Architecture_Comparison.md](../../Architecture_Comparison.md)）。

## アーキテクチャの数値

| 項目 | 値 |
|---|---|
| データ幅 | 8 bit |
| 命令幅 | 18 bit（固定長） |
| 汎用レジスタ | 16本（`r0`–`r15`、各8bit） |
| 命令アドレス空間 | PC は16bit。ただし `minc_h.sv` の ROM は 4096 語（`ROM_ADDR_WIDTH = 12`） |
| データアドレス空間 | 16bit（ただし絶対アドレッシングが届くのは 0–1023） |
| フラグ | キャリー1bit（`PSR` bit0） |
| 実行方式 | 非パイプライン・4状態ステートマシン（1命令 = 4サイクル） |
| 割り込み | 4本・レベルトリガ・固定優先度・1段 |

## レジスタ

汎用レジスタは16本すべて対等ですが、`r12`–`r15` はメモリアクセス時に
**レジスタペア**としても読めるようになっています。

| ペア名 | 構成 | 主な用途 |
|---|---|---|
| X | `{r13, r12}`（`r12` が下位バイト） | 汎用のポインタ。グローバル変数・デリファレンス用 |
| Y | `{r15, r14}`（`r14` が下位バイト） | フレームポインタ（`mincc` の呼び出し規約） |

ハードウェア上は `ldm/stm rp+n` の `rp` フィールドは**任意の偶数レジスタ**を
指定できます（`r0:r1`, `r2:r3`, … も可）。X/Y は慣習的な名前にすぎません。

> 実装メモ: レジスタファイルには `regs_hi[]` という「奇数番レジスタのミラー」が
> 別に持たれています。ペアの上位バイトを読むために読みポートを3本にするのを
> 避けるためで、`rp` フィールドが `{ppp, 1'b0}` の形をしていることを利用して
> 下位バイトは通常の `rs` 読みポートから、上位バイトは `regs_hi[rs[3:1]]` から
> 1サイクルで取っています。

`mincc` が使う際のレジスタの役割分担（呼び出し規約）は
[toolchain/internals.md](../toolchain/internals.md) を参照してください。

## 実行サイクル

```
S_FETCH → S_DECEXEC → S_MA → S_WB → S_FETCH → ...
```

| 状態 | やること |
|---|---|
| `S_FETCH` | ROM から命令語をラッチ（`instr <= rom[pc]`）。同時に割り込み受付判定 |
| `S_DECEXEC` | デコードと演算。`PC += 1`。`calr`/`ret`/`decs` はここで SP を更新 |
| `S_MA` | メモリアクセス（アドレス確定・スタック調整） |
| `S_WB` | レジスタ／PC／PSR への書き戻し。分岐はここで PC を更新 |

したがって**すべての命令が一律4サイクル**です。例外は `stm`/`ldm` で、
外部から `wait_req` が返っている間 `S_WB` に留まります（ウェイトステート）。

`halt`（`= jr -1`、命令語 `3FFFF`）は自分自身へ無限ジャンプします。
シミュレーション時（`` `define SIM ``）は `$finish` でシミュレータを止めます。

## ALU

ALU は「1本の8bit加算器を最大限使い回す」形で書かれています。

- `add`/`adc`/`sub`/`sbc`/`lt`/`ltc` は同じ加算器を共有します。
  `subop[1]` が減算（`b` を反転＋キャリーイン1）、`subop[0]` がキャリーフラグ
  からのキャリーインを選びます。`lt`/`ltc` は和ではなく**借り**を結果として読みます。
- さらにこの加算器は **AGU（アドレス生成）とも共有** されています。
  ALUグループの命令はメモリにもSPにも触れず、メモリ／スタック系の命令は
  ALUを使わないので、1本のキャリーチェーンで両方を賄えます
  （16bit幅の加算器を8bit×2段で書き、ALUは下位バイトのキャリーアウトを
  Cフラグとして取り出す）。
- ただし `calr` だけは「`pc+1` と `sp-1` を同じ状態で必要とする」ため、
  PC用の加算器は別に持っています。

Cフラグが定義されるのは `add`/`adc`/`sub`/`sbc`/`rr`/`lt`/`ltc` だけです。
それ以外の命令（`mov`/`or`/`and`/`xor`/`chz`/`mul`/`mulh`）の実行後、
**Cフラグの値は不定**になります（保存もされません）。詳細は [isa.md](isa.md)。
