# 割り込み

割り込みハードウェアを持つのは **`minc_h.sv` だけ**です。
`minc_p2.sv` / `minc_p5.sv` には `irq_in` ポートがありません。

## ハードウェア仕様

| 項目 | 内容 |
|---|---|
| 要求線 | `irq_in[3:0]`、**レベルトリガ** |
| 優先度 | 固定。`irq_in[0]` が最優先 |
| 多重割り込み | **不可**（1段のみ、ネスト非対応） |
| 追加命令 | `reti` のみ |
| 許可・禁止 | `PSR` の `IE` ビット（メモリマップドレジスタの読み書き） |

### 関連レジスタ

| データアドレス | 名前 | 内容 |
|---|---|---|
| `0x0002` | `PSR` | bit0 = キャリー、bit1 = `IE`、bit2-7 予約（読むと0） |
| `0x0003` | `PSR_SHADOW` | `PSR` の1段自動退避先 |

### 割り込みベクタ

**命令アドレス空間**（PC / ROM 側）にあります。データ空間の `0x0002`/`0x0003` とは
別のバスなので、数字が近くても衝突しません。

| 要求線 | 命令アドレス |
|---|---|
| `irq_in[0]` | `0x0001` |
| `irq_in[1]` | `0x0002` |
| `irq_in[2]` | `0x0003` |
| `irq_in[3]` | `0x0004` |

ベクタは**1語しかない**ので、実際のハンドラへは `jr <ラベル>` で飛ばします。

### 受付時の動作

`S_FETCH` で `IE && |irq_in` が成立すると、その時フェッチした命令は**実行されず**、
4状態を使って次の擬似命令が実行されます。

1. 実行されなかった命令のアドレス（= 現在の `PC`）を2バイト push
2. `PSR_SHADOW = PSR`（1段自動退避）
3. `PSR = 0`（`IE` が落ちるので、ハンドラ内では割り込み禁止）
4. `PC = ベクタアドレス`

`reti` は `ret` と全く同じ動作に加えて `PSR = PSR_SHADOW` を行います。
これで `IE` とキャリーが同時に復元され、割り込まれた側から見れば
何も壊れていない状態に戻ります。

> 実装上、受付時の `PSR` は「`IE` だけクリア」ではなく**丸ごと 0** です。
> キャリーも一旦落ちますが、`PSR_SHADOW` に退避済みで `reti` が丸ごと
> 戻すので、割り込まれた側からは保存されているのと同じことになります。
> ただし **ハンドラの先頭ではキャリーは 0 になっている**点は覚えておいてください。

### 汎用レジスタは自動退避されません

`r0`–`r15` はハードウェアでは一切退避されません。
手書きの `.asm` でハンドラを書く場合は、使うレジスタを自分で `push`/`pop`
してください。`mincc` の `[[isr]]` は**これを自動でやります**（後述）。

## mincc から使う

使い方の実例は [guide/interrupts-howto.md](../guide/interrupts-howto.md) を参照。
ここでは言語仕様としての定義を書きます。

### `[[isr]]` / `[[isr=N]]`

関数定義に付ける属性です。

```c
void [[isr = 0]] timer_interrupt() {
    TIMER8_STATUS = 0b00000001;   // 要因をクリア
    millis_count = millis_count + 1;
}
```

- `[[isr=N]]`（`N` は `0`–`3`）を付けると、`mincc` が `mincasm` の `.org` を使って
  **ベクタ `N`（命令アドレス `0x0001+N`）へ自動配置**します。
- `N` を省いた `[[isr]]` は、正しい形（`reti` で終わる・レジスタ退避つき）の
  ハンドラを生成しますが、自動配置はしません。手書きの `.asm` 側で
  `jr` を置いて呼び出す形になります（`tests/fixtures/irq_vector.asm` 参照）。

`[[isr=N]]` が1つでも存在すると、`mincc` の出力の先頭が次の形に変わります。

```asm
.org 0x0000
jr __crt0_start
.org 0x0001
jr timer_interrupt     ; [[isr=0]] があれば
.org 0x0002
reti                   ; 未使用のスロットは reti で埋まる
.org 0x0003
reti
.org 0x0004
reti
.org 0x0005
__crt0_start:
mvi r14,0
...
```

未使用スロットの `reti` は、想定外の `irq_in` パルスに対する安全な復帰です
（`minc_h.sv` はレベルが立っていれば無条件に push してジャンプするため）。

`[[isr=N]]` を使わないプログラムの出力は**従来どおり変化しません**
（`example/*.hex` の互換性を保つため）。

### 制約（コンパイル時にチェックされます）

- 引数を持てない
- 値を返せない（`return 式;` はエラー。`return;` は可）
- 直接呼び出せない（`reti` で終わるため、通常の `calr` で呼ぶと `PSR` が壊れる）
- 同じベクタ番号を2つの関数が要求するとエラー
- ベクタ番号は 0–3

### レジスタ保護

`mincc` は ISR 本体が**実際に使うレジスタ**を自動的に `push`/`pop` します。
通常の呼び出し規約（`r0`–`r5` caller-saved / `r6`+ callee-saved）よりも厳しく、
`r0`–`r13` すべてが保護対象になります。割り込みには「事前に退避しておいた
呼び出し元」が存在しないためです。

加えて、Xポインタ（`r12:r13`）の退避／復元が本体全体を囲む形で入ります。

内部の仕組みは [toolchain/internals.md](../toolchain/internals.md) を参照。

### `sei()` / `cli()`

割り込みの許可・禁止は組み込み関数で行います（avr-libc と同じ名前）。

```c
sei();   // IE = 1
cli();   // IE = 0
```

`PSR` は `stm`/`ldm` の絶対アドレスモードでしか触れないので、どちらも
リード・モディファイ・ライトに展開されます。

```asm
; sei()
ldm r0,2
mvi r1,2
or  r0,r1
stm 2,r0

; cli()
ldm r0,2
mvi r1,253
and r0,r1
stm 2,r0
```

`[[address=0x02]] psr; psr = 2;` と直接書く方法と違い、読んだ値を書き戻すので
`PSR` bit0（キャリー）が保存されます。使用する `r0`/`r1` はどの文の境界でも
死んでいるので、呼び出し側で退避する必要はありません。

`sei`/`cli` は**他に同名の宣言が無いときだけ**組み込みとして解釈されます。
`char sei = 5;` と書けばそちらが優先されるので、既存コードを壊しません。
（`asm` は本物の予約語なので、こちらはシャドウできません。）

## リセット直後は割り込み禁止

`PSR` は `2'b00` にリセットされ、**crt0 は `IE` を触りません**。
`[[isr=N]]` を書いただけでは割り込みは来ません。プログラム側で
`sei()` を呼ぶ必要があります（`example/blink.c` 参照）。

## 既知の制約

- **同期化回路（シンクロナイザ）がありません。** `irq_in` は CPU と同一クロック
  ドメインである前提です。非同期な外部信号を直接つながないでください。
- **レベルトリガ + 自動マスク**なので、割り込み要因を ISR 側でクリアする前に
  `IE` を立て直すと（`reti` 経由であっても）即座に再突入するリトリガーループに
  なり得ます。ハンドラの**先頭で**要因をクリアしてください。
- パイプライン版（`minc_p2.sv` / `minc_p5.sv`）は割り込み非対応です。
- Gowin トップの UART `INTR` ピンは未配線です（タイマの `O_OVF_INT` のみ
  `irq_line[0]` につながっています）。
