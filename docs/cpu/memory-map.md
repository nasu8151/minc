# アドレス空間とメモリマップ

minc は**ハーバードアーキテクチャ**です。命令とデータは完全に別のバスにいます。
アドレスの数字が近くても衝突しません（割り込みベクタの `0x0001` と
`PSR` の `0x0002` は別空間です）。

## 命令空間（ROM）

| 項目 | 値 |
|---|---|
| 語長 | 18 bit |
| PC | 16 bit |
| `minc_h.sv` の ROM 実体 | **4096 語**（`ROM_ADDR_WIDTH = 12`） |
| `minc_p2.sv` / `minc_p5.sv` の ROM 実体 | 65536 語 |
| 初期化 | `$readmemh("program.hex")`、テスト時は `test.hex` |

`minc_h.sv` の PC は16bitのままですが、ROM のアドレスには下位12bitしか
使っていません。合成器に「PCの到達範囲」を証明させずにブロックRAMへ
落とすためです（LUTベースのフォールバックを避ける）。

つまり **`minc_h.sv` ではプログラムは 4096 命令まで**です。それを超えると
アドレスが折り返します。

### 固定アドレス

| 命令アドレス | 用途 |
|---|---|
| `0x0000` | リセットベクタ（PC のリセット値） |
| `0x0001` | IRQ0 ベクタ（最優先） |
| `0x0002` | IRQ1 ベクタ |
| `0x0003` | IRQ2 ベクタ |
| `0x0004` | IRQ3 ベクタ |

割り込みを使わないプログラムでは `0x0001`–`0x0004` はただの普通の命令領域です
（`mincc` の crt0 がそのまま置かれます）。`[[isr=N]]` を使ったときだけ
`mincc` がベクタテーブルを敷き、crt0 を `0x0005` 以降へずらします。
詳細は [interrupts.md](interrupts.md)。

## データ空間

アドレスバスは16bitですが、**絶対アドレッシング（`stm n` / `ldm n`）が
届くのは 10bit = `0x0000`–`0x03FF` だけ**です。それより上は
レジスタペア経由（`stm rp+n` / `ldm rp+n`）でしかアクセスできません。

```
0x0000 ┌──────────────────────────┐
       │ CPU内蔵レジスタ (SP/PSR) │  ← CPUが内部で応答。外部メモリではない
0x0004 ├──────────────────────────┤
       │ 周辺回路 (MMIO)          │  ← 実装依存（下記）
0x0100 ├──────────────────────────┤
       │ グローバル変数           │  ← mincc が 0x0100 から割り当て
       ├──────────────────────────┤
       │ （未使用）               │
0x0400 ├──────────────────────────┤  ← 絶対アドレッシングの上限
       │ ペア相対でのみ到達可能   │
       ├──────────────────────────┤
       │ スタック（下方向に伸びる）│  ← SP は 0x0000 から下へ = 0xFFFF から
0xFFFF └──────────────────────────┘
```

### CPU 内蔵メモリマップドレジスタ

`address[15:2] == 0`、つまり **`0x0000`–`0x0003`** は CPU 自身が応答します。
外部メモリのデータは無視されます（`cpu_mmio_hit`）。

| アドレス | 名前 | 内容 |
|---|---|---|
| `0x0000` | `SP_L` | スタックポインタ 下位バイト |
| `0x0001` | `SP_H` | スタックポインタ 上位バイト |
| `0x0002` | `PSR` | bit0 = キャリー、bit1 = `IE`（割り込み許可）、bit2-7 予約（読むと0） |
| `0x0003` | `PSR_SHADOW` | `PSR` の1段自動退避先。`reti` がここから復元する |

**SP がメモリマップされている**のが minc の特徴です。専用の SP 操作命令を
持たずに済ませるためで、`mincc` のプロローグ／エピローグは

```asm
ldm r14,0        ; Y = SP  （フレームポインタの取得）
ldm r15,1
...
stm 0,r14        ; SP = Y  （フレームの巻き戻し）
stm 1,r15
```

のように読み書きします。SP を**下げる**だけなら `decs n` が1命令で済みます。

> 注意: `PSR` への書き込みは `data_out[1:0]` の2bitだけが反映されます。
> `PSR` を直接 `stm` すると**キャリーフラグも一緒に上書きされる**ので、
> 割り込み許可の切り替えは読み・修正・書き戻し（`mincc` の `sei()`/`cli()`）で
> 行ってください。

### 周辺回路（MMIO）

`0x0004` より上のマップは**どのトップレベルを使うかで変わります**。

#### シミュレーション（`verilog/minc_tb.sv`）

| アドレス | 名前 | 内容 |
|---|---|---|
| `0x0004` | `PORTA_OUT` | 出力ラッチ。`PORTA_DIR` で 1 のビットだけ書き込まれる |
| `0x0005` | `PORTA_DIR` | 方向レジスタ（1 = 出力、リセット時は全入力） |
| `0x0006` | `PORTA_IN` | 入力（テストベンチでは常に 0） |
| `0x0010`〜 | RAM | `ram_ce = address > 0x000F` |

#### FPGA（`gowin/minc/src/minc_gw_top.sv`）

| アドレス | 名前 | 有効化 `define` |
|---|---|---|
| `0x0004`–`0x0006` | PORT A（OUT / DIR / IN） | `PORTA` |
| `0x0008`–`0x000F` | UART（16550互換IP） | `UART` |
| `0x0010`–`0x0017` | I2C マスタ | `I2C` |
| `0x0018`–`0x001F` | 8bit インターバルタイマ | `TIMER8` |
| `0x0100`〜 | RAM（Gowin ブロックRAM） | 常時（`ram_ce = address > 0x00FF`） |

各レジスタの詳細は [fpga.md](fpga.md) と
[guide/io-and-peripherals.md](../guide/io-and-peripherals.md) を参照。

> **`define` は使う前に確認してください。** これらはすべて
> `minc_gw_top.sv` の先頭でコメントアウト／有効化を切り替える方式で、
> 現在の作業ツリーでは**全部コメントアウトされています**。
> `UART` を有効にすると `WAIT`（ウェイトステート）も自動で有効になります。

### グローバル変数

`mincc` はアドレス指定のないグローバル変数を **`0x0100` から順に**
割り当てます（`mincc/ast.c` の `head->var_alloc_ptr = 0x100`）。
シミュレーション用テストベンチでも FPGA でもここは RAM なので、
どちらでも同じように動きます。

`[[address = N]]` を付けた変数は任意のアドレスに置けます。MMIO はこれで叩きます。

```c
char [[address = 0x04]] PORTA_OUT;
char [[address = 0x05]] PORTA_DIR;
```

> グローバル変数の自動割り当ては現状**型サイズを見ずに1バイトずつ**
> 進みます。`int` のグローバルを2つ以上並べると重なります。
> [known-issues.md](../known-issues.md) を参照。

### スタック

- リセット時 `SP = 0x0000`
- `push` は**プリデクリメント**なので、最初の push は `0xFFFF` に書かれる
- 以降、下方向（アドレスの小さい方）へ伸びる
- グローバル変数領域（`0x0100`〜）まで伸びると壊れる

`mincc` が生成する crt0 は `main` の戻り値を2バイト push してから `halt` するので、
正常終了時の `SP` は `0xFFFE` になります。テストはこれをスタック健全性の
チェックに使っています（`sp_value == 65534`）。

## ウェイトステート

`stm`/`ldm` の実行中、CPU は `avma`（valid memory access）を上げます。
外部が `wait_req` を上げている間、CPU は `S_WB` に留まって待ちます。

- `push`/`pop`/`calr`/`ret` は **`wait_req` を見ません**。
  スタックは必ず高速なメモリに置いてください。
- Gowin のトップレベルでは、RAM 以外（= 周辺回路）へのアクセスのとき
  シフトレジスタで数サイクルのウェイトを挿入しています。
  UART / I2C の IP がバスに追従するために必要です。
